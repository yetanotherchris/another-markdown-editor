# Implementation Plan: Rename Application to MarkdownMeister

**Branch**: `019-rename-to-markdownmeister` | **Date**: 2026-08-08 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/019-rename-to-markdownmeister/spec.md`

## Summary

The application is renamed from "Another Markdown Editor" to **MarkdownMeister**.
The rename covers the whole application identity: the window title and HTML
`<title>` (`MarkdownMeister`), the packaged executable (`markdownmeister`,
`markdownmeister.exe` on Windows), the package identifiers (`markdownmeister` in
`package.json`/`package-lock.json`), the application ID
(`com.yetanotherchris.markdownmeister`), the release artifact prefix
(`markdownmeister-<version>-<os>-<arch>.<ext>`), the Scoop manifest and Homebrew
formula (renamed files `markdownmeister.json` / `markdownmeister.rb`), the update
scripts, the CI workflow, and all source identifiers derived from the old name
(CSS design tokens `--mm-*`, test seams `MM_*`, the on-disk config folder
`appData/markdownmeister`, `ame-*` test temp prefixes). The GitHub repository URL
(`yetanotherchris/another-markdown-editor`) is explicitly NOT renamed (spec
Assumptions; it appears only as a download/homepage URL).

The user chose **full cleanup** (decision log below): the rename also covers
abbreviations of the old name (`AME_*` env vars, `--ame-*` CSS tokens, the
`ame` config folder, `ame-*` temp dirs), and the active spec 022's required
config path is renamed to `~/.config/markdownmeister/` to keep the rename
complete (resolving an explicit FR-015 vs. spec-022 conflict).

## Technical Context

**Language/Version**: TypeScript 5.8, strict: true, across main, preload and renderer.

**Primary Dependencies**: Electron 43 (unchanged), React 19, `@milkdown/crepe` 7.21.3, electron-builder 26, electron-vite 5. No new runtime dependencies.

**Storage**: unchanged — user filesystem + `config.json` in `appData`; the config
folder is renamed `ame` → `markdownmeister` as part of the rename.

**Testing**: Vitest 4 (node project for `tests/main`, jsdom for `tests/renderer`); Playwright via `npm run test:e2e` (build + launch); ESLint + `tsc --noEmit` gates.

**Target Platform**: Windows, macOS, Linux desktop.

**Project Type**: Desktop application (Electron), three build targets, released from GitHub Actions on tag.

**Performance Goals**: none new — the rename is static configuration and identifier text; no runtime behaviour changes.

**Constraints**: Renderer sandboxed (no Node); the packaged artifact names and the
update scripts/manifests must stay mutually consistent; the repo URL is not
renamed; archived specs are untouched; the package-lock is regenerated by npm.

**Scale/Scope**: One mechanical rename across ~20 files plus spec artifacts; no
functional change to the editor.

  favour of the rename: spec 022's required path becomes

  and its migration sources (`%APPDATA%/ame/…`) become the new
  `%APPDATA%/markdownmeister/…`. Recorded in spec 022's `## Clarifications`.

  of the old name, not just the three literal strings: `AME_USER_DATA_DIR` →
  `MM_USER_DATA_DIR`, `AME_CONFIG_DIR` → `MM_CONFIG_DIR`, `AME_E2E_HEADED` →
  `MM_E2E_HEADED`, `--ame-*` → `--mm-*` CSS tokens, `.ame-spelling-error` →
  `.mm-spelling-error`, the `'ame-spellcheck'` plugin key → `'mm-spellcheck'`,
  `appData/ame` → `appData/markdownmeister`, and `ame-*` test temp prefixes →
  `mm-*`.
- **2026-08-08 — Repo URL stays.** `https://github.com/yetanotherchris/another-markdown-editor`
  (and the bare `yetanotherchris/another-markdown-editor`) remains wherever it

## Phase 1 Design decisions

**The naming map is the contract.** A single mapping table (old string → new
string per context) in [contracts/rename.md](./contracts/rename.md) drives every
edit; the implementation tasks apply it file by file, and the verification task
greps for the old strings. Keeping the map in one contract prevents a partial
rename.

**electron-builder identity.** `package.json` sets `name: markdownmeister` and
`productName: MarkdownMeister`; `electron-builder.yml` sets the authoritative
`appId: com.yetanotherchris.markdownmeister`, `productName: MarkdownMeister`,
`executableName: markdownmeister`, and `artifactName: markdownmeister-${version}-…`
for each platform. This flows `app.name` (macOS menu label), the taskbar/dock
label, the `.app` bundle name (`MarkdownMeister.app`), and the launcher binary.

**Window title.** `src/renderer/index.html` `<title>` becomes `MarkdownMeister`;
Electron derives the window/taskbar title from it and productName supplies the OS
metadata. No `BrowserWindow` option change is needed.

**Release definitions.** The Scoop manifest file is renamed
`another-markdown-editor.json` → `markdownmeister.json` and the Homebrew formula
`Formula/another-markdown-editor.rb` → `Formula/markdownmeister.rb` (class
`Markdownmeister`). `updatescoop.ps1`/`updatebrew.ps1` are rewritten to the new
manifest/formula paths and the `markdownmeister-<version>` asset names; the CI
workflow's upload globs, required-artifact set, and auto-commit file pattern are
updated. The manifests keep the current `0.0.96` version + hashes — they are
regenerated by the release workflow on the next tag, at which point the renamed
assets actually exist.

**Config folder + test seams.** `recentItemsConfigPath()` keeps reading from the
same `appData` root but the folder is `markdownmeister` instead of `ame`. The
`AME_*` environment seams become `MM_*`. CSS design tokens `--ame-*` become
`--mm-*` (with the spelling-error class and plugin key following), and `ame-*`
test temp prefixes become `mm-*`.

## Deferred / later features

- Renaming the GitHub repository itself (`yetanotherchris/another-markdown-editor`) — explicitly out of scope (spec Assumptions)
- Migrating existing `appData/ame` settings/recent-items into the renamed folder — spec 019 accepts state not carrying over; spec 022's migration story later supersedes the folder
- The `--ame-*` token values themselves are unchanged — only the token names

## Complexity tracking

| Violation | Why needed | Simpler alternative rejected because |
|-----------|------------|-------------------------------------|
| Config folder renamed `ame` → `markdownmeister` with no migration of the existing `appData/ame/config.json` (settings, MRU list, window state) | The on-disk identity should match the new name (full-cleanup decision); the spec explicitly accepts state not carrying over and spec 022 later defines its own migration | Keeping `ame` as a legacy folder with a one-time copy — adds migration code with data-integrity risk for user convenience files the spec already discounts |
