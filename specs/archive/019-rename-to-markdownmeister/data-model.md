# Data Model: Rename Application to MarkdownMeister

The rename operates on the **Application Identity** entity (spec "Key
Entities"). There are no runtime data structures added or changed; the model
below is the set of identity fields and the files that own them.

## Application Identity

The combination of names that identify the application to users, the operating
system, and package managers.

| Field | Old value | New value | Owned by |
|-------|-----------|-----------|----------|
| `productName` (human-facing) | `Another Markdown Editor` | `MarkdownMeister` | `package.json`, `electron-builder.yml` |
| `name` (package identifier) | `another-markdown-editor` | `markdownmeister` | `package.json`, `package-lock.json` (npm-regenerated) |
| `appId` (OS application ID) | `com.yetanotherchris.another-markdown-editor` | `com.yetanotherchris.markdownmeister` | `electron-builder.yml` |
| `executableName` (launcher binary) | `ameditor` | `markdownmeister` | `electron-builder.yml` |
| macOS `.app` bundle name | `Another Markdown Editor.app` | `MarkdownMeister.app` | derived from `productName` |
| HTML/window title | `Another Markdown Editor` | `MarkdownMeister` | `src/renderer/index.html` |
| Config folder (under `appData`) | `ame` | `markdownmeister` | `src/main/recentItemsPath.ts` |
| Test seams (`*_CONFIG_DIR`, `*_USER_DATA_DIR`, `*_E2E_HEADED`) | `AME_*` | `MM_*` | `src/main/*`, `tests/e2e/launch.ts`, `playwright.config.ts` |

## Release Asset

A build output file whose name encodes name, version, platform, architecture.

| Property | Old pattern | New pattern |
|----------|-------------|-------------|
| Windows archive | `ameditor-<v>-windows-x64.zip` | `markdownmeister-<v>-windows-x64.zip` |
| Windows installer | `ameditor-<v>-windows-x64.exe` | `markdownmeister-<v>-windows-x64.exe` |
| macOS archives | `ameditor-<v>-macos-{arm64,x64}.zip` | `markdownmeister-<v>-macos-{arm64,x64}.zip` |
| macOS DMG | `ameditor-<v>-macos-{arm64,x64}.dmg` | `markdownmeister-<v>-macos-{arm64,x64}.dmg` |
| Linux AppImage | `ameditor-<v>-linux-x64.AppImage` | `markdownmeister-<v>-linux-x64.AppImage` |

Owned by `electron-builder.yml` (`artifactName`), asserted by
`.github/workflows/build-release.yml` (upload globs + required-artifact set),
consumed by `updatescoop.ps1` / `updatebrew.ps1`.

## Package Manifest

A metadata file describing how to download and install the application.

| File | Old | New |
|------|-----|-----|
| Scoop manifest | `another-markdown-editor.json` | `markdownmeister.json` (`bin` alias `markdownmeister`) |
| Homebrew formula | `Formula/another-markdown-editor.rb` (class `AnotherMarkdownEditor`) | `Formula/markdownmeister.rb` (class `Markdownmeister`, installs `MarkdownMeister.app` / `bin/markdownmeister`) |
| `homepage` / download URL | repo URL | unchanged (repo is not renamed) |

## Validation rules

- The three literal old strings (`ameditor`, `another markdown editor`,
  `another-markdown-editor`) MUST NOT appear in any non-archived, non-build
  source file except as part of the GitHub repository URL (SC-002, R5).
- All derived abbreviations (`AME_*`, `--ame-*`, `ame` folder, `ame-*` prefixes)
  MUST be renamed to their `MM`/`mm`/`markdownmeister` equivalents (R6).
- `version` and SHA256 hashes in the manifests are unchanged by this feature;
  the release workflow regenerates them on the next tag (R4).
- `package-lock.json` MUST match the new `package.json` `name` (spec Assumptions:
  regenerated by npm, not hand-edited).

## State transitions

None. The rename does not add, remove, or transition any runtime state.
